# 经验记忆与自我修正规则

> 本规则要求 AI 在遇到失误、新问题、新经验时，**主动**将教训写入项目记忆和规则文件，避免同类错误重复发生。

## 触发条件（满足任一即触发）

| 触发场景 | 动作 |
|----------|------|
| 编辑代码后编译/构建失败 | 记录到 `pitfalls.md` + 更新 `edit-safety.md` |
| 同一类错误第 2 次出现 | **立即**添加规则到 `edit-safety.md` 或新建规则文件 |
| 发现社区已有解决方案 | 记录到 `pitfalls.md`（含社区链接）+ 更新 `decisions.md` |
| 测试通过但功能不工作 | 记录到 `pitfalls.md` + 更新 `testing.md` 添加 E2E 要求 |
| 依赖版本冲突 | 记录到 `pitfalls.md` + 更新 `edit-safety.md` Rule 11 |
| 补丁/脚本破坏构建产物 | 记录到 `pitfalls.md` + 更新 `edit-safety.md` Rule 10 |
| 用户指出 AI 未发现的问题 | 记录到 `pitfalls.md` + 分析根因 + 添加预防规则 |
| >1 次失败尝试才定位根因 | 记录到 `pitfalls.md`（含失败尝试 + 正确路径） |
| 用户纠正做法/偏好 | 记录到 `conventions.md` 或 `decisions.md` |

## 写入目标

| 文件 | 写入内容 | 格式 |
|------|---------|------|
| `.agents/memorys/pitfalls.md` | 问题 + 原因 + 方案 + 验证 + 禁止 | 五段式（见模板） |
| `.agents/memorys/decisions.md` | 架构/技术决策 + 理由 + 参考 | `## D{N}: 标题` + `- **日期/决定/理由/参考**` |
| `.agents/memorys/conventions.md` | 开发约束/用户偏好 | 强制规则 + 检查命令 |
| `.agents/rules/common/edit-safety.md` | 可机械执行的检查规则 | `### N. 规则名` + 检查命令 + 阻塞条件 |
| `.agents/rules/common/testing.md` | 测试覆盖要求 | 测试类型 + 执行命令 + 通过标准 |

## 写入时机

1. **即时写入**：发现问题的当下就写入，不等到会话结束
2. **修复后验证**：写入后验证规则是否可执行（有具体命令，不是空话）
3. **去重检查**：写入前 `grep` 目标文件，确认不重复

## 规则质量标准

每条规则必须满足：

| 标准 | 说明 |
|------|------|
| **可执行** | 包含具体的 shell 命令或检查步骤，不是"注意 XXX" |
| **可验证** | 有明确的通过/失败标准（如 `grep -c '{' == grep -c '}'`） |
| **有阻塞** | 明确说明不通过时怎么办（如"Block: never run build on invalid JSON"） |
| **有先例** | 引用实际发生的错误（如"2026-07-28 server/index.ts 缺少 `}` ×3"） |

## 反模式（禁止）

| 反模式 | 正确做法 |
|--------|---------|
| "以后注意" | 写入具体检查命令到规则文件 |
| 只记录不预防 | 每条 pitfall 必须对应一条可执行规则 |
| 规则写"小心编辑" | 写 `grep -c '{' file && grep -c '}' file` |
| 等用户提醒才记录 | 发现即记录，不等用户指出 |
| 记录到对话中不持久化 | 必须写入 `.agents/` 下的文件 |

## 捕获清单（每次触发时自问）

1. **什么错了？**（现象）
2. **为什么错？**（根因）
3. **正确做法？**（方案）
4. **如何预防？**（检查命令 / 约束）
5. **存到哪里？**（按写入目标表）

## 平凡修复逃生舱

1 行修复 / 无分支 / 无副作用 → 1 行捕获即可，不用完整模板。

## 模板（pitfalls.md 条目必须包含）

```markdown
### [问题标题]
- **问题**: [现象描述]
- **原因**: [根因分析]
- **方案**: [正确做法]
- **验证**: [检查命令或测试方法]
- **禁止**: [错误做法，标注"禁止重蹈"]
```

## 预防升级（仅高频/高成本教训）

- 重复出现或耗费 >3 轮才定位的教训 → 添加 CI 门禁或 pre-commit hook
- 低频/低成本的教训 → 仅记录到 pitfalls.md，不加自动化门禁
